### 3.2 `build_routes()` — 路由表（总装核心）

```python
def build_routes() -> dict[str, object]:
    """返回 {route_name: 组件类/工厂} 供 Shell 的 routes prop 使用。"""
    return {
        "home": HomeScreen,                  # 文档 2 主屏
        "settings": MdSettingsApp,           # 四个内置应用
        "clock": MdClockApp,
        "gallery": MdGalleryApp,
        "calculator": MdCalculatorApp,
        "shade": ShadeScreen,                # 文档 3 系统场景
        "lock": LockScreenScene,
        "recents": RecentsScreen,
    }
```

**路由数据流**：
- `HomeScreen.apps` 里的每项 `on_open` 应指向 `lambda name=r: shell_navigate(name)`——但 `build_routes` 只提供路由表，**实际 `navigate` 由调用方（Shell 的 `on_route_change` 或宿主）执行**（高自由）。
- 具体接线：`build_routes()` 返回的组件类由文档 1 的 `build_app(routes=build_routes())` 注入 Shell；Shell 的 `open_route(route)` 更新内部 `route` ref 并触发 `on_route_change`。App 点击 → `props["on_open"](route)` → 调用方调 `shell navigate`（可封装在 data.py 的 helper，但不得改 shell.py）。
- 提供 `make_open(route)` helper 返回可传给 app 的 `on_open` 回调闭包（内部只记录目标 route，交给宿主执行），降低调用方接线成本。

## 4. `run_showcase.py` 规格 — 无头验证/截图

仿 `protocol/showcase/lib/showcase_app.py:main` 的无头模式，扩展为多场景：

```python
def main() -> int:
    """无头渲染各场景 N 帧，验证不崩、可出图。"""
    routes = build_routes()
    for scene in ("home", "settings", "clock", "gallery",
                  "calculator", "shade", "lock", "recents"):
        app = build_app(width=360, height=800, routes=routes)
        app.root_component  # Shell：可通过修改 initial_route ref 或在 build_app 传 initial_route
        # 渲染若干帧（VAPOR_DEMO_FRAMES，默认 2）
        for _ in range(frames):
            app.tick()
        # 可选：app.surface 落盘 PNG（若 Surface 提供 to_png/save_image；否则跳过）
        app.unmount()
    return 0
```

- 环境变量：`VAPOR_DEMO_FRAMES`（每场景帧数，默认 2）、`VAPOR_OS_DARK`、`VAPOR_OS_SEED`、`VAPOR_OS_SCENES`（逗号分隔场景子集，默认全部）。
- **截图为可选增强**：若 `Surface` 有 `to_png()`/`save_image()` 就落盘到 `vapor_os/_shots/`；没有则只验证不崩（测试断言 `app.tick()` 无异常即可）。**不要**为此改 `Surface`（属库文件）。
- 场景切换：通过 `build_app(initial_route=scene)` 注入（文档 1 的 `build_app` 已支持 `routes`；若未暴露 `initial_route`，本份可扩展 `build_app` 调用时传参——但**不得改 app.py**，改为在 `run_showcase` 里构造 Shell 子类注入 initial_route）。

## 6. 实现要点与坑

1. **路由表是唯一总装点**：所有场景/应用通过 `build_routes()` 注册，文档 1 的 `build_app(routes=...)` 注入 Shell；不要在 data.py 里直接 `navigate()`。
2. **延迟 import 防循环**：`data.py` import 文档 1/2/3 的模块，而文档 1 的 `build_app` 延迟 import `data`——注意不要形成 import 环。若 `build_app` 里 `from . import data` 发生在函数内（延迟），则 data.py 顶层 import app.py 是安全的（函数未执行时不会触发）。
3. **示例数据走角色名不写 hex**：文案中文用 `type_style` 已有的组件处理，数据层只给字符串。
4. **无头模式不阻塞**：`VAPOR_DEMO_FRAMES>0` 时走 for 循环 tick 后 return，不进 `app.run()`（否则 CI 卡住）。
5. **截图能力检测**：落盘前 `hasattr(surface, "to_png")`，无则跳过，保持跨版本兼容。
