# Vapor OS 演示 · 执行文档 1：项目骨架与启动入口

> 面向执行者的可并行实施文档。本系列共四份，**文件所有权零重叠，可同时开工**。
> 本份负责 Vapor OS 演示的**骨架与启动链路**：目录结构、App 配置、`install` 装配、主题/字体/动态取色初始化、`VaporShell` 挂载、无头运行入口。
> 目标：产出一条能"一键启动、无头出帧"的最小可运行链路，其余三份（主屏/系统场景/应用接入）在此骨架上挂内容。

---

## 0. 范围边界（先读，避免越界）

| 本份 **要做的** | 本份 **明确不做的** |
|---|---|
| `vapor_os/` 演示目录骨架 + `__init__.py` | ❌ 主屏/桌面内容（文档 2） |
| `app.py`：`build_app()` 装配入口（主题/字体/provider/Shell） | ❌ 通知中心/QuickSettings/锁屏/最近任务场景（文档 3） |

**关键铁律**：本份只**新建** `python/examples/vapor_os/` 下的骨架文件，**不修改任何现有文件**。所有对已落地能力的调用（主题/字体/组件）都是只读 import。

## 2. 依赖的已落地能力（只读调用，不得修改）

```python
import Vapor as V
from Vapor import md3, vos                          # 24 + 15 个组件 provider
from Vapor.vos_base.cjk import install_cjk          # 中文装配（幂等）
from Vapor.theme import (
    Theme, current_theme, set_theme,
    seed_to_scheme, baseline_light, baseline_dark,  # 动态取色 / 基线
)
from Vapor.vos.shell import VaporShell              # OS 根容器
```

- **provider 装配**：`md3.install()`（24 个）+ `vos.install()`（15 个）在 `build_app()` 里各调一次；二者都用全局 `ui.register`（host=None）。
- **中文**：`install_cjk()` 幂等（`vos_base` 已做标志位），`build_app()` 调一次即可，Shell 挂载时也会兜底调一次（无害）。
- **主题**：默认 `set_theme(Theme(baseline_light()))`；支持环境变量 `VAPOR_OS_DARK=1` 切深色；`VAPOR_OS_SEED=0xFF6750A4` 时用 `seed_to_scheme(seed, dark=...)` 动态取色（Material You）。
- **App 配置**：分辨率用环境变量 `VAPOR_OS_W`/`VAPOR_OS_H`（默认 `None` 让 Surface 自动，典型手机 1080×2400）；`fps=60`；`dirty_rects=True`（开启脏区，呼应已落地的脏区优化）。

## 3. `app.py` 规格 — `build_app()`

```python
def build_app(width=None, height=None, *, seed=None, dark=None,
              routes=None, use_native=True) -> V.App:
    """装配并返回已 mount 的 App。其余文档/脚本只调这个函数。"""
```

**执行顺序（务必按此顺序，避免主题/字体晚于构建）**：

1. **主题先行**：在任何组件 `build` 之前 `set_theme(...)`——因为组件颜色在 `build` 里取 `current_theme().role()`。用 `seed` 则 `set_theme(seed_to_scheme(int(seed, 0), dark=bool(dark)))`，否则 `Theme(baseline_dark() if dark else baseline_light())`。
2. **中文装配**：`install_cjk()`（返回 False 时不报错，退回点阵字体，CI 无字体环境可跑）。
3. **provider 装配**：`md3.install()` + `vos.install()`（注册 39 个组件）。
4. **routes 准备**：`routes = dict(routes or {})`；若为空，从 `vapor_os.data` 里延迟导入默认 routes（文档 4 提供；未落地时用空字典兜底，Shell 会显示"未注册路由"提示，不崩）。**延迟 import** 避免骨架依赖文档 4。
5. **挂载 Shell**：`app = V.create_app(VaporShell, width=width, height=height, use_native=use_native, dirty_rects=True, props={"routes": routes, ...})`。注意 `create_app` 是否接受 props——若不接受，改为 `V.App(VaporShell, ..., registry=...)` 并在 `root_component` 上用类属性/上下文注入 routes（见坑 1）。
6. `app.mount()` 后返回。

> **routes 注入的正确姿势**：`VaporShell` 的 `props` 含 `routes` 字典、`initial_route`。App 挂载时通过 `root_component.instantiate(renderer, props_in, slots)` 传 props——`create_app` 未必透传 props，执行者需确认 `create_app` 签名（读 `ui/app.py` 的 `create_app`）；若不支持，直接构造 `V.App(...)` 并给 `VaporShell` 做一个带默认 props 的子类（本份内定义 `class OSShell(VaporShell): props = {**VaporShell.props, "routes": ...}` 由 `build_app` 动态生成）。

## 4. `main.py` 规格 — CLI 入口

仿照 `protocol/showcase/lib/showcase_app.py:main` 的模式：

```python
import os
from .app import build_app

def main() -> int:
    app = build_app()
    print("[vapor-os] ready:", app.surface.width, "x", app.surface.height)
    frames = int(os.environ.get("VAPOR_DEMO_FRAMES", "0") or 0)
    if frames:                       # 无头/CI：渲染 N 帧后退出
        for _ in range(frames):
            app.tick()
        print("[vapor-os] rendered", frames, "frames")
        return 0
    app.run()                        # 交互：进入帧循环
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

运行方式（写进 README 由文档 4 汇总）：
```
PYTHONPATH=python python3 -m examples.vapor_os.main
VAPOR_DEMO_FRAMES=3 VAPOR_OS_DARK=1 PYTHONPATH=python python3 -m examples.vapor_os.main
```

## 5. 实现要点与坑

1. **`create_app` 可能不透传 props**：先读 `ui/app.py` 的 `create_app` 实现。若不支持 props，用 `V.App` 直接构造 + 子类化 `VaporShell` 注入 routes（见 §3 坑 1）。**不要**在库里改 `create_app`。
2. **主题必须早于 build**：`set_theme` 在 `app.mount()` 之前调用；否则组件首帧颜色是旧主题（effect 会重跑但首帧可能闪一下）。
3. **install 幂等性**：`md3.install()`/`vos.install()` 重复调用会重复注册同名组件；`build_app()` 只调一次，多次 `build_app()` 用于测试时先 `V.ui.register` 的清理或用新 registry，注意别污染全局（测试里可用 mock）。
4. **延迟 import 文档4**：`build_app()` 里 `from . import data` 必须放在 try/延迟分支，文档4未落地时不能让骨架 import 失败。
5. **脏区首帧**：`App.mount()` 已 `mark_full()`，首帧全帧；`dirty_rects=True` 下无变化帧不上传（已落地优化），骨架不用额外处理。
6. **无 CJK 字体环境**：`install_cjk()` 返回 False 属正常；测试不得假设字体一定装上。

## 6. 验收测试（`test_vapor_os_boot.py`）

- `test_build_app_returns_mounted`：调用 `build_app(width=360, height=800)`，断言返回 `V.App`、`app.root` 非空、`app.surface` 尺寸正确。
- `test_providers_installed`：断言 `V.ui.COMPONENTS` 含若干关键名（`MdButton`/`MdStatusBar`/`MdAppGrid`/`MdSettingsApp`）；total >= 39。
- `test_theme_seed_dark`：`build_app(seed="0xFF6750A4", dark=True)` 后 `current_theme().role("primary")` 非默认色（与 baseline 不同）；不抛异常。
- `test_dark_env`：`VAPOR_OS_DARK=1` 时主题为深色（role 值与浅色不同）。
- `test_no_font_graceful`：mock `install_cjk` 返回 False，`build_app()` 仍能 mount。
- `test_no_routes_graceful`：`routes=None` 且文档4未落地时 Shell 显示"未注册路由"提示，不抛异常。
- `test_headless_frames`：设 `VAPOR_DEMO_FRAMES=2`，`main()` 返回 0，无异常（不进入阻塞 `run()`）。
- `test_no_lib_modified`：本份只新建文件（编排层 git diff 核对，测试里可断言 `Vapor/vos/*` 未出现本演示专用符号）。
